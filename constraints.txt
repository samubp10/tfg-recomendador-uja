# Versiones exactas del entorno con el que se midieron los experimentos.
#
# Por qué existe: `pyproject.toml` declara rangos abiertos (`lancedb>=0.37`,
# `sentence-transformers>=3.0`, ...), que es lo correcto para un paquete
# ---no obliga a nadie a una versión concreta---, pero significa que una
# instalación hecha dentro de seis meses resolverá otras versiones y las
# cifras de `docs/experimentos/` dejarán de ser repetibles sin que nada lo
# advierta. Este fichero guarda la fotografía; el `pyproject` sigue diciendo
# lo que el proyecto necesita de verdad. Son dos cosas distintas y por eso
# no se fusionan en una.
#
# Cómo se usa, para repetir un experimento con el entorno con el que se midió:
#
#     pip install -e ".[dev,index]" -c constraints.txt
#
# NO lo usa el CI, y es deliberado: el CI instala con los rangos abiertos
# justamente para que una versión nueva que rompa algo se vea el día que sale
# y no el día de la defensa. Fijarlo allí convertiría el CI en una prueba de
# que el pasado sigue funcionando.
#
# La comparativa de bases vectoriales (IT-31) fija además sus versiones con
# `==` dentro del propio `pyproject.toml`: ahí el pin es parte del diseño del
# experimento, porque compara el comportamiento POR DEFECTO de tres bases.
#
# Se regenera con el entorno del proyecto activado:
#
#     pip freeze | grep -v "^-e " > constraints.txt   # y se le vuelve a poner esta cabecera
